# Experiment registry: one canonical ID per experiment

GENERATED by `tools/build_registry.py` from `docs/experiments/registry.json` and the record. Do not edit by hand: change `registry.json`, then run the tool. `--check` is the gate.

**If you have an old ID, use the lookup table below.** Every experiment, re-score, port, control and adjudication in this repository has exactly one canonical ID of the form `E##`, and every stored result belongs to exactly one run of it, `E##.n`. The old names (T14, R1, CV3, DA1b, …) still appear in file names, commit messages and older documents. They are kept as aliases, because files are pinned by path in the provenance record and cannot be renamed.

## The rules

1. A lineage is one question together with every run, re-score, port, control and adjudication of it. Membership is decided from provenance: which stored results a run consumes and pins, and which document owns them.
2. A lineage keeps the number it already had: its E-number if it had one, otherwise the number of its exploratory T-ID (T14 is E14) when that slot is free.
3. A lineage with no usable number takes the next number from E67 upward, in order of its first stored result (the earlier of the git commit that first added a results file and the file's provenance timestamp). T13 is the one exploratory ID whose slot was taken (E13 already existed), so it is E67.
4. Runs are numbered E##.1, E##.2, ... in the order the provenance record implies: a run whose stored inputs include another run's results comes after it, and otherwise the earlier first stored result comes first. The old IDs survive as aliases, so E52.3 and R1 name the same run.
5. A number is never reused and never reassigned. File names are not changed: results files, scripts and pre-registrations are pinned by path and hash in the provenance record, so renaming them would break the record this registry indexes.

## The experiments, by finding

Every experiment belongs to exactly one finding: the claim in the paper it bears on, or, for the last two groups, the instrument checks and the work that did not enter the paper. The README's findings table names every experiment; `--check` fails if one is missing there.

Runs are listed with the old ID each one was known by, and the date of its first stored result. Documents link to the pre-registration and the description. Modules are the `repro/exp/` invocations that reproduce the run, with their tier (T0 recomputes from stored JSON, T1 re-scores stored maps on CPU, T2 refits on a GPU).
